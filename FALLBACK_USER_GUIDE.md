## Common Questions

### Q: Is my Gemini API key working?
**A**: Yes! Your valid Gemini key is set and working fine.

### Q: Will fallback affect my normal usage?
**A**: No! When you have a valid API key, the system uses Gemini normally. Fallback only activates when needed.

### Q: How do I know if fallback is being used?
**A**: Check the response:
- Backend logs will show "Using local LLM fallback" or "Using heuristic fallback"  
- API response includes `"used_fallback": true`
- `"llm_used"` shows which provider was used

### Q: Is the local LLM as good as Gemini?
**A**: The local LLM provides good quality answers but Gemini is better. However, the local LLM works completely offline without any API key!

### Q: What if I don't want to use fallback?
**A**: Keep your valid API keys set. The system will always try the cloud API first and only fall back if it fails.

## Troubleshooting

### Issue: "I want to test fallback but don't want to lose my API key"
**Solution**: Your API key is safely stored. Just run the diagnostic script:
```bash
python test_fallback_simple.py
```
It temporarily uses invalid keys for testing, then you can restore your real key.

### Issue: "How do I restore my API key after testing?"
**Solution**: Use the frontend Settings tab or run:
```python
import requests
requests.post("http://localhost:8000/config", json={
    "key_name": "gemini_api_key",
    "key_value": "YOUR_ACTUAL_KEY_HERE"
})
```

### Issue: "I don't see fallback working"
**Solution**: This is actually good! It means your API key is valid and working. Fallback only activates when the API fails.
